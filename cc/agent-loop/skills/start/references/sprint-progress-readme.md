# スプリント進捗ステータス

進行中・未着手のスプリントを管理する。完了分は [完了一覧](./完了/README.md) に保管する。
進行中・未着手の進捗の正はこのファイルとする。

## ステップ定義

| Step | 役割 | 内容 |
|---|---|---|
| 1 | planner | 機能・ゴール定義 |
| 2 | generator | 契約起票 |
| 3 | evaluator | 契約承認（差し戻しは 2→3 を反復） |
| 4 | generator | 実装 |
| 5 | evaluator | 最終判定（不合格は 4→5 を反復、3回連続不合格でユーザーに報告） |

## 更新ルール

- この表の更新は**メインエージェントの責務**。サブエージェント（planner / generator / evaluator）は自分のタスクに集中し、更新しない。メインエージェントがサブエージェントの完了報告を受け取るたびに該当スプリントの表を更新する。
- 「担当」はその Step を実際に実行する AI コーディングツール名（例: Claude Code / Codex）を記録する。Step ごとに担当が変わりうる。着手時に記入し、未着手の Step は空欄にする。引き継いで着手した場合は現在の担当へ更新し、推測で埋めない。
- ステータスは「未着手／着手中／完了／中止」の4種。Step 5 の合格時だけ「完了（合格）」と記載する。**完了・完了（合格）・未着手には備考を書かない。**
- 着手中のステップのみ、備考に未完了の内容（差し戻し理由・残タスクなど）を記載する。「中止」の場合は理由と、後続作業の参照先（該当あれば）を備考に記載する。
- Step 5 が「完了（合格）」になったら、一覧行と詳細表を `完了/README.md` へ、`sprint-N.md` を `完了/sprint-N.md` へ移す。移動したファイルへの参照を更新し、リンク切れを確認する。採番時は完了分も確認する。
- evaluator の判定詳細（スコア・改善提案など）は各 `sprint-N.md` 末尾に記載する。このファイルには載せない。
